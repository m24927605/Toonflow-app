# Text Node

Writes, saves, and generates text in Markdown, for scripts, storyboard notes, or asset analysis.

## Inputs and outputs

- Inputs accept text, image, and video references.
- Outputs the node's current full Markdown string, which can be connected to downstream nodes that accept text input.

## Usage

1. The node shows the text as a Markdown preview. Click "Edit" to open the rich text editor, or switch to source mode to edit the Markdown directly.
2. To generate with AI, select the node, enter your request below, and choose a model; if there is none, add one in Settings first.
3. Connect reference nodes and explain in the prompt how they should be used.
4. Click the generate button and the text appears progressively; newly generated content replaces the current text output.
5. After generation you can keep editing by hand, then connect the text output to the next production nodes.

The text is saved automatically to the node's `content.md`, and downloads use the `.md` format. If the content on disk conflicts, you can first view and copy the current text, then choose to reload it from disk; the AI prompt below is edited independently.

The node ships its own Markdown editing and preview implementation and only reuses the Tiptap, Marked, and DOMPurify dependencies provided by the host. Rich text editing normalizes the Markdown; to keep raw HTML exactly as written, use source mode.

How well image and video references are understood depends on the selected model.

"Generate shot list" turns this text, taken as the script, into a shot list. It adds a text node named "Shot list" to the right, connected from this node (below the shot lists made earlier from the same script), and starts its generation at once with the uncensored Qwen3.6-35B-A3B-Uncensored-HauhauCS-Aggressive model on Colab CLI (add the Colab CLI provider in Settings first), whatever model this node uses. The model reads the whole script, then splits it into shots with time ranges by the pacing of the story, and writes one Markdown table with the columns Shot, Time, Shot size, Camera, Action, Dialogue, Cast and State, which "Build shot nodes" reads directly. When the canvas has images with the Character role, their character names are given to the model, which must use them in the Cast and State columns even where the script calls the people differently, so "Build shot nodes" ticks each shot's cast; the script node stays connected as the original script. The script must fit the model's 32K context; a longer one fails with an error instead of being read in part.

The node's role, picked from the menu at the start of its toolbar, decides which flow actions it shows, never its content or label: a **Script** offers "Generate shot list", a **Shot list** offers "Build shot nodes" and "Prepare videos", and a **Shot prompt** offers "Distribute prompts"; a plain text node shows none of them. The flows set the roles of what they create: "Generate shot list" makes a Shot list node, and "Build shot nodes" makes Shot prompt text nodes, keyframes with the Keyframe role and their shot number, and video nodes with their shot number. Image and video nodes carry their own roles (Keyframe, Character, Scene, Previs layout; Previs), which is how the shot flow finds them.

"Create previs" (shown on a shot list) adds one Director's Studio node to the right, fed by the shot list and the script feeding it, using the uncensored Qwen3.6-35B-A3B model on Colab CLI. It holds one instruction per shot, built from the shot's row: the first shot also builds the set at real-world scale with every person as one cylinder, and later shots keep the set and start each person where the previous shot left them. The Director's Studio then blocks the shots one at a time (see its readme); each confirmed shot is exported as a Previs layout image with its shot number and the blocking measured in the scene, and "Build shot nodes" uses both: the layout as a reference of that shot's keyframe, and the blocking (each person's side of the frame and distance from the camera, the camera's height and tilt) as a fixed line of the keyframe prompt and of the shot's text node instructions, so neither image nor text model has to guess where people stand. A shot list makes one previs node; a second press only points to it.

"Prepare videos" (shown on a shot list) takes every shot whose keyframe is generated to a ready-to-run video node. For each such shot it creates a MiniMax H3 video generation node when the shot has none, to the right of its keyframe and connected to it, in the first-frame mode with the shot length as duration (at least 4 s), and then has the uncensored Qwen3.6-35B-A3B model on Colab CLI write the H3 prompt from the whole original script and shot list, one shot after another: the first-frame line for `<Picture 1>`, `integrated_multimodal_description` with the shot's action, camera and dialogue in its original language, `overall_soundscape` with only the sounds of the scene, and `non_diegetic_music: N/A`, since music is laid over the joined film later. Dialogue is never typed by the model: it writes `[[LINE n]]` markers where each line is spoken, and the exact words of the shot's dialogue cell are filled in as `<d>[Language] ...</d>`, the language taken from the words' script (kana Japanese, Hangul Korean, Han Chinese, otherwise English), with one speaker ID per person across the whole shot list.

Every written prompt is preflighted before it is filled in. Checks that need no model come first: the H3 structure, `non_diegetic_music: N/A`, the spoken lines matching the dialogue cell word for word with the right language, no unfilled markers, at most 7,000 characters and a 4–15 s duration. Then the same model reviews the prompt against Gate 1 of the cinematic-director QC checklist, scoring story function (20), blocking and camera (15), first-frame consistency with the cast and character-state cells (25), prompt hygiene (20) and continuity with the previous and next shots (20); the weighted score is computed from its 0–5 category scores. A prompt with a failed check or a score under 80 is rewritten once with the findings and checked again. The result is stored on the video node, which shows it above the prompt and asks before generating from a failed prompt; editing the prompt afterwards marks the result as out of date. A report lists every shot's score and findings, which the review writes in the interface language; shots that pass can still carry suggestions. The review reads text only, so the keyframe image itself is not compared with the prompt.

Each person is one column of the dialog's cast table; a person with several outfits (see the image nodes' readme) gets a menu per shot, preset to the outfit the shot's row mentions (its state cell first), and only that outfit's views are connected and named. Keyframe and video nodes built here carry the trained character LoRAs of their cast from the workspace's `loras/` folder (Qwen-Image LoRAs for keyframes, MiniMax H3 LoRAs for videos), keyframes also the Qwen-Image scene LoRA named like their scene images, and the generation nodes add their trigger words to the prompt. A generation loads at most 4 LoRAs, so a shot with four people keeps theirs and drops the scene LoRA. The dialog lists each person (video and keyframe LoRA) and scene (keyframe LoRA) with ✓ or ✗, flags scene images without a scene name, and says to click Train LoRA on their images and build once training finishes, since nodes built earlier do not pick up a LoRA trained later.

When a character in a shot's cast cell has a trained character LoRA (see the image nodes' readme), the video node records it and loads it at generation, and the prompt writer must name that person with the LoRA's trigger word every time (such as `abcdef woman in the pale kimono`); the preflight fails a prompt that never uses it.

When a shot has a Previs video (exported when its previs shot was confirmed), it is connected to the shot's video node after the keyframe, so the prompt calls it `<Video 1>`: the writer must add a sentence naming it a grey-box previs used only for blocking (where each person stands and moves, relative positions, timing and the camera move) whose shapes, materials, colours and markings are not taken, and follow its order and timing; the preflight fails a prompt that does not name it that way. "Build shot nodes" connects it the same way, with a fixed line in the video template.

Existing video nodes are filled only while their prompt is empty or still holds `{{shot}}`. A dialog lists the nodes to create and fill and the shots still waiting for keyframes, and sets the video resolution (480p, 720p or 1080p, 1080p by default) and aspect ratio (the keyframe's own by default, or 16:9, 9:16, 1:1, 4:3 or 3:4; another ratio crops or pads the first frame) for every video it prepares and every existing video node of the shot list, written or not; it opens even when there is nothing to write, to change only those settings. The choices are remembered on the shot list; video generation is never started, so review each prompt first. Run it again after generating more keyframes to add their videos.

The timing check is the last step of "Generate shot list": when the model finishes, the shot list (table rows with a time range, or `Shot_001 | ... | 3s` lines) is checked for shots over 8 s, gaps or overlaps between time ranges, a median shot over 5 s, or no shot list at all. A list with problems goes back to the same model once with the problems listed and is replaced by its rewrite; then a short note gives the shot count, total and median length, or a dialog lists the problems that remain. Only text nodes with the Shot list role run this check.

"Distribute prompts" fills generation nodes from a text split into `### Shot 3` (or `### 第 3 鏡`) sections: each section goes to the image or video generation node that belongs to the same shot (its shot number, set by "Build shot nodes" or in a keyframe's role menu). References the section does not name with `{{ref N}}` are disconnected and the remaining markers renumbered; a depth-control model keeps its first reference. A section without any `{{ref N}}` keeps every connection, so the node's reference check reports it. A confirmation lists the nodes to fill and any shot without a node before anything changes. When a node's prompt contains `{{shot}}`, only that marker is replaced and the text around it is kept, so fixed parts such as `{{ref 1}}` for the set and one `{{ref N}}` per character can stay in the node while the text model writes only the shot description; distributing again replaces the previously inserted section and keeps edits made around it. A cast line the text model writes anyway (`Cast: A, B`, or `人物：A、B`) is dropped and changes nothing: who is in a shot is fixed when its node is built.

"Build shot nodes" turns the shot list into nodes shot by shot. A shot without a keyframe node gets an image generation node named `Shot N keyframe (time)`, connected to the scene and character images; a shot whose keyframe is generated gets a video generation node named `Shot N video (time)`, starting from that keyframe with the shot length as duration (the video template and per-shot text asks for no background music, only dialogue and the sounds of the scene, so music can be laid over the joined film later), without waiting for the other shots. So a few shots can be taken all the way to video to check the result, and building again later adds the rest; one build can create keyframe nodes for some shots and video nodes for others, each kind with its own prompt template in the dialog. Shots whose keyframe node exists but is not generated yet are listed and skipped, and shots that already have their nodes are skipped. Existing keyframes and video nodes are matched to shots by their shot number, never by label. References come from the images selected on the canvas, or else from every image, by role: Character images sharing a character name become one character with several views, Scene images are the sets, and images without a role are left out. An image with the Previs layout role and a shot number (a colour frame exported from the Director's Studio, with its shot set in its role menu) is connected to that shot's keyframe after the template's references, with a line asking to follow its composition, camera angle and where each person stands while taking no appearance from it. A dialog shows the plan, lets you untick references, pick each character's default view, set who is in each shot and edit the `{{shot}}` prompt template. The cast of each shot is preset from a cast column of the shot list (a header such as `Cast` or `出場角色`, holding the character names; an empty cell means nobody) or, without one, ticks everyone. A person counts as in the shot when any part of them is in frame, such as a hand, their back or a silhouette, so their reference keeps skin, hair and clothing consistent; the text node is then asked to say which part is framed; a character-state column (a header such as `State` or `人物狀態`, for example `日女：正座於座墊，雙手捧茶杯`) becomes a fixed line of that shot's template next to the description, and its text node must keep posture and held objects consistent with it; without the column the text node is told to carry posture over from the earlier rows; each keyframe node then connects and names only its own cast, and its text node is told exactly who is in the shot. A master shot is suggested and preselected: the shot a shot list names on a line such as `Master shot: 4 - reason` (or `主鏡頭：第 4 鏡 — 理由`), which "Generate shot list" asks its model to write after the table, or else the shot listing the most people in its cast cell (an empty marker such as `none` or `無` counts as nobody, so an empty establishing shot never wins over a shot with people), then the widest shot size (from a column such as `Shot size` or `景別`), then the earliest; the dialog shows why, and another shot or none can be picked. A master shot can be chosen for keyframes: every other keyframe node also connects the master shot's keyframe as its last reference and its template asks to match its lighting, colour, clothing and props while following its own composition, so generate and approve the master shot first. Text nodes connected into the shot list are taken as its original script: each per-shot text node then reads the script first and the shot list second, so it describes the shot from its row with detail from the whole story. The dialog can also add one text node per shot connected to this shot list with instructions to write that shot's description for Distribute prompts.
